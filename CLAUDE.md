# PlanPal

Calendar app with a one-way social sharing layer. Expo (mobile), Next.js (web)
and Supabase, in a pnpm/Turborepo monorepo.

Every claim in this file was checked against the repo. If something here
disagrees with the code, the code is right — fix this file.

## Commands

Run from the repo root; Turborepo fans out to each workspace.

- Install: `pnpm install`
- Dev: `pnpm dev` · web only: `pnpm --filter @planpal/web dev` (http://localhost:3000) · mobile: `pnpm --filter @planpal/mobile dev`
- Lint: `pnpm lint` · Typecheck: `pnpm typecheck` · Build: `pnpm build`
- Unit tests: `pnpm test`
- Integration tests: `pnpm test:integration` (needs the local stack up)
- Local Supabase (needs Docker): `pnpm db:start` / `pnpm db:stop` / `pnpm db:reset` / `pnpm db:diff` / `pnpm db:push`
- Contract: `pnpm contract:validate` · `pnpm contract:generate`
- Recurrence mirror: `pnpm recurrence:sync` · `pnpm recurrence:check`

`pnpm format` runs Prettier with `--write` over the **whole repo**. Don't. The
checkout is CRLF and is not Prettier-clean, so it rewrites hundreds of files
and buries your change. Format only what you touched:
`npx prettier --end-of-line auto --write <paths>`.

## Tech stack

- TypeScript 5.6, Node 22 (`.nvmrc`)
- **pnpm 9** (`pnpm@9.12.0` via corepack) — never npm/yarn; the lockfile is `pnpm-lock.yaml`
- Next.js App Router + React for `apps/web`; Expo + expo-router for `apps/mobile`
- Supabase: Postgres 17, Auth (GoTrue), RLS, Deno Edge Functions. Supabase CLI pinned to `2.117.0` by the `db:*` scripts — use those, not a bare `supabase`.

## Structure

- `apps/web/` — Next.js App Router
- `apps/mobile/` — Expo / React Native
- `packages/api-client/` — the only network boundary (see below)
- `packages/api-contract/` — `openapi.yaml`, the integration contract
- `packages/types/` — shared types, generated from the contract
- `packages/recurrence/` — RRULE expansion engine
- `packages/calendar-core/` — date/grid logic shared by both apps
- `packages/ui/`, `packages/design-tokens/` — component contracts + primitives
- `packages/analytics/` — typed KPI event contracts
- `supabase/functions/` — the API: 10 Edge Functions (`events`, `occurrences`, `export`, `friend-code`, `me`, `healthz`, `notify-scheduler`, `parse`, `parse-worker`, `feedback`) plus `_shared`
- `supabase/migrations/` — forward-only schema + RLS policies

**Do not hand-edit** `packages/types/src/generated/` — regenerate with
`pnpm contract:generate`. `contract.yml` fails the PR on `git diff --exit-code`.

**Never reformat `supabase/functions/_shared/recurrence/*`.** It is generated by
`pnpm recurrence:sync`, and `pnpm recurrence:check` fails CI on byte drift.

## Rules that are actually enforced

- **All network access goes through `@planpal/api-client`.** `eslint.config.mjs`
  bans importing `supabase-js` (`no-restricted-imports`) and calling `fetch`
  (`no-restricted-globals`) outside it. This is a lint failure, not a convention.
- **The OpenAPI contract is the source of truth.** Types are generated from it
  and drift-gated in CI.
- **RLS is the authority on visibility**, not the client. All seven tables in
  `public` have row security enabled. Six have explicit policies;
  `notification_sends` deliberately has none (service-role only), and
  `grants.test.ts` asserts both that distinction and that no SECURITY DEFINER
  function is executable by `public`/`anon`/`authenticated` bar an allowlisted
  `delete_me()`.
- **Every new table** must enable RLS and define explicit policies in the same
  migration. Every new SECURITY DEFINER function ships with
  `revoke execute from public, anon, authenticated` in the same migration.

## Testing

Two runners, deliberately:

- **Vitest** — `api-client`, `calendar-core`, `analytics`, `design-tokens`,
  `types`, `apps/web`, and the integration suite in `supabase/tests`.
- **`node --test`** — `@planpal/recurrence` (compiles to `dist/` first).
- **Jest** — `apps/mobile`.

Coverage floors, where they exist:

| Package                                    | Floor                                                                   |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| `calendar-core`                            | 90% lines/functions/branches/statements                                 |
| `recurrence`                               | 90% lines, 90% functions, 85% branches (CLI flags in its `test` script) |
| `api-client`, `analytics`, `design-tokens` | 70%                                                                     |
| `types`, `apps/web`, `supabase/tests`      | none, deliberately — each config says why                               |

Running a single file with `--coverage` can fail the package's global
threshold even when every test passes. That is an artefact of the filter, not a
real failure; check the unfiltered run before believing it.

The integration package is `@planpal/integration-tests` and its script is
`test:integration`, **not** `test`.

`docs/TESTING.md` forbids tests against a cloud Supabase project. Use the local
stack.

## Database & migrations

- Migrations are **versioned and forward-only**. Never edit one already applied
  anywhere; add a new timestamped file in `supabase/migrations/`.
- `pnpm db:reset` applies every migration from scratch plus `seed.sql`.
- `supabase/seed.sql` is the local fixture (`alice@example.com` /
  `scott@example.com`, password `password123`). `supabase/seed.demo.sql` is the
  public demo dataset, dated relative to `now()`, applied explicitly.
- Inserting into `auth.users` directly: set `confirmation_token`,
  `recovery_token`, `email_change_token_new` and `email_change` to `''`. They
  are the only string columns with no default, and GoTrue scans them into
  non-nullable Go strings — leaving them NULL makes every sign-in fail with
  500 "Database error querying schema", which no row-level assertion can see.
- Full strategy: `docs/BOOTSTRAP.md`.

## Environment gotchas

- **Docker must be running before `pnpm db:start`.** If the output has no
  `FUNCTIONS_URL`, the stack is half-started — `pnpm db:stop`, then
  `pnpm db:start`.
- **`[analytics] enabled = false` in `supabase/config.toml` is deliberate.**
  `supabase_vector` cannot work on Windows. Don't flip it back; read container
  logs with `docker logs <name>` instead of Studio's Logs pane.
- **The edge runtime serves cached isolates.** After editing a handler,
  `docker restart supabase_edge_runtime_planpal`.
- **Do not install `@playwright/test`.** It re-resolves `next` through an
  optional peer dependency and dies with `ERR_PNPM_ENOENT`, after which every
  install fails until `pnpm-lock.yaml` is reverted. Isolating it in its own
  workspace package does not help.
- `pnpm --filter` prints a spurious `No projects matched the filters` line and
  still runs the command. Ignore it.

## Git & PRs

- Branch from `main`; don't commit to it directly.
- **Commit messages are prose, imperative, sentence case. No
  conventional-commit prefixes** — match the log, e.g. `Fix the offline path,
the unsaveable edit form, and a swallowed conflict`. Never `feat:`/`chore:`.
- Green before merge: `ci.yml` (lint, typecheck, test, build, Expo pin check,
  recurrence mirror, Edge Function lint + typecheck, integration suite) and
  `contract.yml` (OpenAPI valid, generated types not drifted).
- `deploy-staging.yml` runs on merge to `main`, but only acts when the
  `staging` environment secrets are set; without them it skips with a notice
  and stays green.
